# AI 封面生成 Agent（保险 / 金融垂类）

> 产品界面显示名为 **千川内容平台**

输入**一句主题** → 自动产出**内容分段设计** + **多平台封面**（封面上体现主题信息）。

- **4 类产出物**：直播间封面 / 小红书图文 / 抖音图文 / 抖音视频封面（各自带平台安全区）
- **16 套模板 · 4 个视觉族**：经典稳重、年轻活力、小红书笔记、抖音竖屏
- **2 种排版**：由有没有「主播半身像」自动切换（人物版式 / 无人物版式）
- 内置保险金融合规预检 + 打回重做闭环

纯 Pillow 渲染 + FastAPI + 零构建前端，**无需任何 API Key 即可完整演示**。

**线上地址（无需后端，打开即用）**：<https://cain0624.github.io/qianchuan-content-platform/>

```bash
./run.sh              # 前台启动  → http://127.0.0.1:8848
python3 daemon.py start   # 或后台常驻（setsid 开新会话，不受终端回收影响）
```

## 一、八层编排 + 打回重做闭环

```
L1 输入解析  → L2 内容分段设计 → L3 文案生成 → L4 合规预检闸
   → L5 产出物与模板匹配 → L6 多尺寸渲染 → L7 排版校验闸 → L8 产出
                    ↑                      │
                    └────── 打回重做 ──────┘   L4 命中红线/严重类 → 携带修改建议回写 L3
```

L4 命中红线（BLOCK）/ 严重类（FAIL）时，会把命中词写入 `avoidWords` 预规避并退回 L3 重生成，
复检通过才进入渲染。默认最多打回 2 轮，可在界面调整。

## 二、三个正交维度：平台 × 视觉族 × 排版

三层各管一件事，互不耦合，所以「加一个平台」不用动渲染骨架：

| 维度 | 决定什么 | 取值 |
|---|---|---|
| **platform** 产出物类型 | 画布规格 + 平台安全区 + 推荐尺寸 + 可用模板 | `live` / `xhs` / `dy_image` / `dy_video` |
| **family** 视觉族 | 配色、字体、装饰语言、对齐方式 | `classic` / `youth` / `xhs` / `douyin` |
| **layoutMode** 排版模式 | 有没有半身像 → 排布方式 | `person` / `graphic` |

### 2.1 四类产出物与平台安全区

平台安全区 = **被平台自带 UI 盖住的区域**。关键文字全部落在安全区内，出图后才不会被状态栏、昵称、文案、评论框吃掉。

| 产出物 | 画幅 | 推荐尺寸 | 安全区（顶 / 底） | 视觉特征 |
|---|---|---|---|---|
| **直播间封面** `live` | 5 种 | 1:1 + 9:16 | 0 / 0 | 自持画布无遮挡，走五分区骨架 + 主播挂件 |
| **小红书图文** `xhs` | 3:4 / 1:1 | 3:4 | 3% / 4% | 浅底**超大黑体**标题 + 关键词**荧光高亮** + 顶部作者行 + 底部 `#话题` 标签带 |
| **抖音图文** `dy_image` | 3:4 | 3:4 | 5.5% / 8.5% | 高饱和渐变底 + 超大**描边**标题 + 顶部话题条 + 右下**页码 1/N** |
| **抖音视频封面** `dy_video` | 9:16 | 9:16 | **14% / 22%** | 全屏首帧，底部 22% 让开昵称 / 文案 / 音乐条 / 评论框，右下**时长角标** |

> 抖音视频封面安全区最大：抖音会把封面压在右侧信息栏之下，顶部还有状态栏与搜索栏。
> 文字块因此被约束在 14%~78% 的纵向区间内居中偏上排布。

前端「01 直播主题」里的**产出物类型下拉框**切换后会自动带出该平台的推荐尺寸、锁定对应视觉族、过滤模板列表。

### 2.2 统一模板结构（分区骨架）

所有模板共用**同一套分区骨架**，只在视觉层分化——结构天然统一，风格分得开。

| 分区 | 内容 | 约束 |
|---|---|---|
| A 标签条 / 作者行 | 类目 / 领域标签；小红书为「圆形头像 + 昵称 + 头衔」 | ≤12 字 |
| B 主标题 | 主题提炼（核心信息） | ≤14 字 / 最多 3 行 |
| C 副标题 | 主题延展、利益点、人群指向 | ≤14 字 |
| D 角标徽章 | 开播时间 / 预约 / 限量 | ≤12 字 |
| E 底部信息条 / 话题带 | 机构署名 + 引导语；平台封面上提为 `#话题` 标签带 | ≤18 字 |
| F 画面区 | 半身像（人物版式）/ 图标卡 / 页码 | 不计入文字覆盖率 |
| G 签名胶囊 | 圆形头像 + `姓名·头衔 ｜ 机构名` | 宽度不足时逐级降级 |

### 2.3 两种排版由素材自动决定（唯一开关：有没有「主播半身像」）

| 排版 | 触发 | 直播间封面 | 平台封面（小红书 / 抖音） |
|---|---|---|---|
| **人物版式** `person` | 已选主播半身像 | 横版**左右分栏**（文案左 / 人物右）；方版与竖版**上下分层**（文案上 / 人物下） | 半身像占据**下半屏出血**，文案块上移，作者行与话题带跟在文案块之后（避免被人物压住） |
| **无人物版式** `graphic` | 未选半身像 | 文案居中通栏 + 底部两侧圆角图标卡 | 文案居中构图 + 作者行 + 话题标签带 |

两个版式都遵循同一条硬规则：**人物画在文字下层、文案压最上层**，主题信息永不被遮挡。

直播间封面的几何参数按画幅分三档（`personGeometry`，全部相对画布）：

| 画幅 | 文案宽 | 人物顶界 | 底部出血上限 | 人物宽上限 |
|---|---|---|---|---|
| `wide` 横版（16:9 / 2.35:1） | 53% | 15.5% | 16% | 46% |
| `square` 方版（1:1） | 86% | 40% | 34% | 62% |
| `tall` 竖版（9:16 / 3:4） | 86% | 40% | 26% | 74% |

抠底立绘走「**宽度优先**」：先按人物宽上限取目标尺寸，多出来的高度从画布底部裁掉——
半身像腰际本来就该落在画布外，宁可多裁一点，也不让人物被高度约束挤成一张小图。

前端右栏「模板规范」tab 与生成结果区都实时显示当前排版，并可**一键生成两种排版并排对照**。

## 三、主播素材库（两种角色，均为可选）

**不传素材即默认「无人物版式」**，传了主播半身像才切到「人物版式」。
素材区不再有「不挂」占位卡——点已选中的卡片即是取消挂载，想换就点另一张。

| 角色 | 落位 | 处理 |
|---|---|---|
| `portrait` **主播半身像** | 版式主角 · 画面区 | 自动去头顶留白 → 按 `0.72` 画幅取头肩 → **可选自动抠底** → 缩放到长边 1400 |
| `logo` 机构 Logo | 签名胶囊 / 底部图标卡 | 等比容纳 + 12% 内边距贴到 512 透明画布，保留透明通道 |

> 后端 `assets.py` 仍保留 `avatar`（圆形小标）角色的处理能力，只是**前端入口已下线**：
> 签名行 / 作者行里的头衔改为跟着主播半身像的 `title` 走。

**自动抠底**（上传区可开关）：从四角泛洪抠掉与边角色相近的背景，且只允许抠「与画布边界连通」的区域，
避免误伤人物内部；抠掉比例落在 `5%~92%` 之外判定失败并自动放弃。成功后羽化 + 裁掉多余透明边，
渲染时立绘直接出血并底部柔化融入背景。

**降级链路**（保证任意素材都不破图）：

```
抠底成功 → 出血立绘（底部柔化溶进背景）
抠底失败 / 主动关闭 → 拱形人物卡（上圆下方 + 投影 + 白色内描边，完整落在画布内）
不传半身像 → 无人物版式（文案居中 + 作者行 / 图标卡）
Logo 留空 → 内置字形兜底（三柱增长图形）
```

素材库预置内置示例（示例半身像 / 示例头像 / 示例机构标识）供随时点选，**但不会自动挂载**，
所以首次打开就是干净的无人物版式。

| 管理能力 | 说明 |
|---|---|
| 上传 | 拖拽或点选，支持 jpg / png / webp / bmp，单文件 ≤8MB，可批量，**可选** |
| 角色推断 | 文件名含 `logo` 归 Logo，其余一律当主播半身像 |
| 选用 / 改名 / 删除 | 选中状态存 localStorage（`cvg_assets_v3`）；再点一次已选中的卡片 = 取消挂载 |

## 五、保险金融合规规则库（10 条硬规则）

| 类型 | 层级 | 依据 |
|---|---|---|
| 收益承诺 / 保本保收益 | 红线类 → BLOCK | 《保险法》《人身保险销售行为管理办法》 |
| 绝对化用语 | 严重类 → FAIL | 《广告法》第九条 |
| 夸大保障范围 | 严重类 → FAIL | 《保险法》《广告法》第二十八条 |
| **诱导隐瞒告知** | 严重类 → FAIL | 《保险法》第十六条 |
| 与存款理财类误导类比 | 严重类 → FAIL | 《互联网保险业务监管办法》 |
| 分红万能利益不确定性 | 严重类 → FAIL | 《人身保险产品信息披露管理办法》 |
| 虚假稀缺 / 炒停售 | 提示类 → 自动改写 | 《广告法》《保险法》 |
| 医疗功效 / 变相返佣 | 严重类 → FAIL | 行业监管规定 |
| 权威背书 / 承诺理赔时效 | 提示类 → 自动改写 | 《广告法》 |
| 文字排版密度 | 提示类 → 自动改写 | 平台审核规范 |

只有**提示类**会被自动改写；红线类 / 严重类一律打回重生成，避免"改一改就过"绕过风险。

## 七、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/health` | 运行模式（真实 LLM / 离线合成器） |
| `GET` | `/api/meta` | 场景、模板、风格族、**outputPlatforms**、尺寸（含像素与用途）、分区规范、**两种排版**、**人物几何**、素材角色 |
| `GET` | `/api/rules` | 模板规范 + 排版规范 |
| `POST` | `/api/generate` | 主链路：`{theme, variant, outputPlatform, styleFamily, templateId, assets, sizes, pageTotal, durationLabel, ...}` |
| `POST` | `/api/rerender` | 同文案换模板重渲染（可带素材，尺寸自动按模板所属平台收窄） |
| `POST` | `/api/layout/compare` | **两种排版并排对照**：同一套文案分别按有 / 无半身像渲染（写盘分 `person/`、`graphic/` 子目录，避免同名覆盖） |
| `POST` | `/api/precheck` | 对抗压测：一段文案直接过硬规则闸 |
| `GET` | `/api/metrics` | 数据回流：PASS 率、高频违规、打回分布、生成记录 |
| `GET` | `/api/assets` | 素材列表 |
| `POST` | `/api/assets/upload` | 素材上传（multipart：`file / role / name / title / cutout`） |
| `PATCH` | `/api/assets/{id}` | 改名 / 改头衔 / 改角色 |
| `DELETE` | `/api/assets/{id}` | 删除素材 |

- `assets` 字段：`{portraitId, avatarId, logoId, anchorTitle}` —— `portraitId` 是版式开关。
- `outputPlatform` 是**产出物类型**（`live/xhs/dy_image/dy_video`，决定画布规格与可用模板）；`platform` 是**投放平台**（合规备注用，默认 `alipay_finance`，可选 `alipay_finance / alipay_content / douyin / kuaishou / videohao / taobao`）。两者不是一回事，接口里刻意分开命名。

## 八、设计取舍

1. **封面用模板化渲染而不是 AI 文生图** —— 既要"统一模板结构"又要中文 100% 准确，文生图两点都做不到。`imagePrompt` 保留在产出里，将来想接文生图底图可直接用。
2. **平台安全区做成数据，而不是渲染器里的 if** —— 新增平台只需在 `_spec.platforms` 加一条（画布 + 安全区 + 可用族 + 推荐尺寸），渲染骨架零改动。抖音以后收紧底部遮挡比例，改一个数字即可。
3. **平台专属模板不给选风格族** —— 小红书笔记和高饱和抖音风各有自己的调性，让用户在小红书产出物下选"经典深色厚底"只会产出违和的图。前端直接锁定。
4. **L4 只做文本闸** —— 画面检测（低俗 / 侵权 / 遮挡）属于文档后半部分的法务 Agent。产出里已带 `zoneBoxes`、`textRatio`、`imagePrompt`，接上去不用改渲染链路。
5. **抠底只做「背景色泛洪」这一档** —— 离线跑深度学习抠图（rembg / MODNet）模型体积与耗时都不可控。所以选确定性方案：四角色泛洪 + 连通性约束 + 比例合理性校验，失败就明确降级成拱形人物卡，不做"半透明的残次品"。
6. **人物区不计入文字覆盖率** —— 半身像是画面不是文字，计入会让 `textRatio` 虚高到 20%+ 而误判排版风险。现规则下正常产出稳定在 5%~18%，上限 30% 的闸门才有意义。
7. **两种排版必须分目录落盘** —— 并排对照时两种版式的文件名完全一致，写进同一目录会互相覆盖，前端并排两栏会拿到同一张图。

## 十、线上部署（无后端也能跑）

**线上地址**：<https://cain0624.github.io/qianchuan-content-platform/>
**仓库**：<https://github.com/cain0624/qianchuan-content-platform>（public）

### 10.1 为什么没有后端也能跑

GitHub Pages 只能托管静态文件，不能跑 Python。所以把**同一份 `core/`** 通过 WebAssembly 搬进浏览器：

```
浏览器                              服务器（本机）
┌────────────────────────┐         ┌──────────────────┐
│ app.js                 │         │ FastAPI server.py│
│   api(path, body)      │         │   core/*.py      │
│        │               │         └──────────────────┘
│   bridge.js 探测 ./api/health
│        ├─ 200 且 JSON ───┼── HTTP ──► 真后端
│        └─ 否则          │
│             Pyodide + Pillow
│             api_facade.py ──► 同一份 core/
└────────────────────────┘
```

- `static/bridge.js` 探测 `./api/health`，**必须同时满足 200 且 content-type 是 JSON**。只判 200 会踩坑：SPA 兜底会把 `index.html` 以 200 吐回来，前端会误判"有后端"。
- 走 Pyodide 时 `Pillow 10.2.0` 在 Pyodide v0.26.4 包清单里是**零依赖**的，`loadPackage("pillow")` 直接可用（实测 30 项能力全绿：中文 truetype、带 alpha 合成、GaussianBlur、ImageChops.multiply、抠底依赖的 floodfill、1080×1440 全流程）。
- 业务代码零改动：`api_facade.py` 只重写 `server.py` 的**路由层**，`core/` 是同一份文件、同一套扁平 import。

### 10.2 字体：90.5MB → 10.61MB

macOS 系统字体线上不存在（且 23.5MB / 66.9MB 太大），用 `tools/subset_fonts.py` 按 GB2312 字集裁字形：

| 字体 | 子集后 | gzip |
|---|---|---|
| sans-regular（Hiragino Sans GB） | 2509.8 KB | 2256.3 KB |
| sans-bold | 2570.4 KB | 2333.3 KB |
| serif-regular（Songti） | 2839.4 KB | 1919.6 KB |
| serif-bold | 2942.1 KB | 1999.0 KB |
| **合计** | **10.61 MB** | **8.31 MB** |

- 覆盖验证：项目数据 896 个非 ASCII 字符**零缺失**，15 条常见句子 163 字符**零缺失**；仅 7 个 GB2312 外极生僻字（濛燚甦靐飝齾龘）不在集内。
- **不要加 `--no-hinting`** —— Hiragino 是 CFF 字体，hint 操作符在 charstring 里，剥掉后抗锯齿边缘会挪位，实测 2.3% 像素差、最大通道差 255。去掉后体积只涨 1.7%，与系统字体渲染**逐像素一致**。`--desubroutinize` 在这里是反向优化。
- **不要加 `--no-subset-tables+=cmap`** —— cmap 保留全部码点而字形被裁，编译时按字形名回查直接 `KeyError: 'cid22354'`（错误信息完全看不出是参数问题）。
- 字体走 **jsdelivr CDN 直连仓库**：同一个 2.3MB 字体 jsdelivr 3.7s vs Pages 32.5s（快 8.7 倍）。**但代码与数据必须走同源相对路径**——CDN 对分支有缓存，改完不生效。

### 10.3 发布流程

```bash
python3 tools/subset_fonts.py     # 1. 字体子集化（改了配色/字集才需要）
python3 tools/smoke_platforms.py  # 2. 后端回归 8/8
python3 tools/parity_check.py     # 3. 对拍：真后端 vs api_facade
python3 tools/build_site.py       # 4. 组装 dist/
python3 tools/deploy_github.py    # 5. 原子提交 + 开 Pages（token 从钥匙串读，不落盘不打印）
```

### 10.4 为什么用 Git Data API 而不是 git push

本机到 github.com 的 smart-http 会 `Empty reply from server`，代理下 `CONNECT tunnel failed 502` —— 但 REST API 照样通。所以 `deploy_github.py` 走 `blob → tree → commit → ref` 一次原子提交（多文件只产生一个 commit），`PATCH refs` 偶发 500 会重试一次，最后回读 `commits/main` 校验并轮询 Pages 到 `built`。

### 10.5 两个只在线上才暴露的坑

1. **`api_facade.py` 没进引擎清单** → 线上 `ModuleNotFoundError: No module named 'api_facade'`。`tools/build_site.py` 把它复制进了 `dist/`，但没计入 `py-manifest.json` 的 core 清单，所以没装进虚拟文件系统。**本地怎么测都测不出来**——本地走 HTTP 模式，压根不装虚拟 FS。修法：`copy_file` 之后 `core_files.append(rel)`。
2. **`.nojekyll` 必须加** —— 不加则 Jekyll 会吃掉 `assets/_builtin/` 这类下划线开头的目录。
3. **`core/guard.py` 命中词排序依赖 CPython hash 随机化**（`sorted(set(matched), key=len)`）→ 同一段文案在不同进程里命中词顺序不同。这是真实缺陷，不只是对拍问题，已改为按 `(-len, patterns 书写顺序)` 完全确定排序。
